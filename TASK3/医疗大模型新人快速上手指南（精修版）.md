# 工具篇：先把环境搭干净

## 0. 先分清五个名词（概念地图）

新手最容易被这几个词绕晕，先记住它们各自是干什么的，后面看到就不会慌。

| 名词 | 一句话解释 | 类比 |
| --- | --- | --- |
| Python 解释器 | 真正执行代码的程序 | 翻译官 |
| Homebrew | Mac 上的命令行软件安装工具 | 程序员的应用商店 |
| pip | Python 的包管理器，负责装第三方库 | 解释器的"进货员" |
| `.venv` | 每个项目独立的依赖隔离目录 | 每个项目一个单独的小盒子 |
| VS Code | 写代码、运行代码的编辑器 | 高级记事本 + 控制台 |

两个最容易搞混的点：

- **你写的 `.py` 文件只是文字**，像一篇作文；真正读它、执行它的是**解释器**。
- **VS Code 本身不会跑 Python**。它只是"写字板 + 控制台外壳"，代码跑起来仍然靠解释器——这也是为什么后面必须给它指定 `.venv`。

## 1. 安装 Python 解释器

Mac 出厂自带一个老版本 Python（`/usr/bin/python3`），版本旧、权限受限，装包时经常出各种奇怪问题。所以我们要另外装一个干净的新版本，推荐 3.12。

**方案 A：Homebrew（推荐）**

```bash
brew install python@3.12
```

验证是否装好：

```bash
python3 --version
pip3 --version
```

**方案 B：官网安装包**

到 [python.org](https://python.org) 下载 macOS 的 pkg 包，一路点下一步即可。

> ⚠️ 禁忌：**不要直接使用 Mac 自带的 `/usr/bin/python3`**。系统组件依赖它，动它容易把系统弄坏，装包也会被权限拦住。

## 2. 配置 VS Code（必装）

1. 安装扩展：左侧边栏点方块图标【扩展】→ 搜索 `Python` → 选作者为 **Microsoft** 的那个 → 安装（会同时带上 Pylance 和调试器）。
2. 打开项目文件夹。**重要：先打开文件夹，不要只打开单个 `.py` 文件**，否则虚拟环境和路径识别都会出问题。

## 3. 建项目并创建虚拟环境

为了不同项目能用不同版本的库，每个项目都要有自己的 `.venv`。假设项目叫 `llm-cli`，放在 `Documents` 下，依次在终端执行：

```bash
cd ~/Documents          # 进入 Documents
mkdir llm-cli           # 新建项目文件夹
cd llm-cli              # 进入项目文件夹
pwd                     # 确认当前所在目录

python3 -m venv .venv   # 创建虚拟环境
source .venv/bin/activate   # 激活；成功后终端前缀会出现 (.venv)
```

激活之后，**所有装包命令都在这个前缀下执行**，这样库只装进本项目：

```bash
pip install <包名>
deactivate              # 退出虚拟环境
```

> 也可以直接在 VS Code 里选择解释器路径 `.venv/bin/python`，效果相同。

## 4. 装包与找包

Python 的第三方库都发布在 PyPI 官方仓库：<https://pypi.org/>。

在网页搜索包名（例如 `openai`、`python-dotenv`），页面上能看到安装命令、文档、版本和示例代码，比命令行搜索可靠得多。

```bash
pip search <包名>   # 不推荐：新版 pip 已基本废弃该功能，优先用网页
```

# 接口篇：在国内调用大模型 API

## 一、先选平台

下面四家都提供 **OpenAI 兼容接口**，用 `openai` 这一个包就能统一切换，国内可直连，且有免费额度：

DeepSeek（深度求索）、通义千问（阿里云百炼）、智谱 GLM、豆包（火山方舟）。

## 二、拿 API Key，写进 `.env`

`.env` 是一个**纯文本文件**，名字就叫 `.env`：前面有一个小数点，没有后缀，不是 `.txt`。它专门用来放密钥、接口地址这类不能外传的信息。

```bash
# 示例：DeepSeek
LLM_API_KEY="sk-xxxxxxxxxxxx"
LLM_BASE_URL="https://api.deepseek.com"
LLM_MODEL="deepseek-chat"

# 换成通义千问时，改成下面这组
# LLM_API_KEY="sk-xxxx"
# LLM_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
# LLM_MODEL="qwen-plus"
```

> 安全提示：`.env` 相当于密码本。不要去压缩、不要贴到聊天窗口、不要提交到 Git 仓库（项目根目录加一个 `.gitignore` 并写入 `.env` 即可）。

## 三、装包

```bash
source .venv/bin/activate      # 先确认在虚拟环境里
pip install openai python-dotenv
```

## 四、跑通第一次调用

新建 `hello.py`，内容如下：

```python
from openai import OpenAI
from dotenv import load_dotenv
import os

load_dotenv()   # 读取同目录下的 .env

client = OpenAI(
    api_key=os.getenv("LLM_API_KEY"),
    base_url=os.getenv("LLM_BASE_URL"),
)
model = os.getenv("LLM_MODEL")

resp = client.chat.completions.create(
    model=model,
    messages=[{"role": "user", "content": "用一句话解释什么是多模态大模型。"}],
)
print(resp.choices[0].message.content)
```

在终端运行 `python hello.py`，能打印出一句回答，就说明整条链路通了。

## 五、换平台只改三行

换平台时**不需要改代码**，只改 `.env` 里的三个值：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。

## 六、三种最常见的报错

| 现象 | 多半是 | 怎么查 |
| --- | --- | --- |
| `ModuleNotFoundError: openai` | 没激活 `.venv`，或包装到了别的环境 | 看终端前缀有没有 `(.venv)` |
| `401 / AuthenticationError` | Key 写错、失效或没读到 `.env` | 打印 `os.getenv("LLM_API_KEY")` 是否为 `None` |
| 连不上、超时 | `base_url` 填错，或该平台需要单独开通 | 对照平台文档的 base_url |

# 协作篇：让 ChatGPT / Claude / Gemini 帮你写代码

它们擅长：解释概念、定位 bug、重构代码、写示例、梳理思路。

它们不擅长：自动读懂你本地的全部文件，自动适配你本机的特殊环境。**所以提示词里要主动交代环境。**

## 通用起手式

```text
我在 Mac，用 VS Code + Python 3.12，项目里有 .venv 虚拟环境，用 openai 库对接 OpenAI 兼容接口。
需求：xxx
只输出代码，不要多余解释，注释精简。
```

## 代码解释 / 逐行拆解

适合看不懂别人的代码或 SDK 文档时使用。

```text
解释下面这段代码做了什么，分点说明，用词简洁，重点讲每行在干什么、为什么这么写。
[贴代码]
```

## 查文档、找参数

```text
openai SDK 的 chat.completions.create 有哪些常用参数？分别是什么作用、默认值是多少？
```

## 三条避坑

1. **不要把完整 API Key 发给任何大模型。** 只贴代码，`.env` 里的 `sk-xxx` 绝对不外发，一旦泄露对方可以直接刷你的额度。
2. **AI 给的代码不要直接复制就用。** 尤其注意版本差异：新版 `openai` 包和旧写法不同；它还可能给你 Windows 的路径和激活命令，而你是 Mac。
3. **不要让它一次写一个很长的复杂项目。** 模块越多越容易幻觉，生成的代码大概率跑不通。拆成小块，一次只解决一个函数、一个报错。

# 实战篇：代码报错时怎么问

**提问模板（三样缺一不可）：**

1. 完整报错信息（从第一行 `Traceback` 到最后一行，不要只截最后一句）
2. 对应的代码片段（出问题的那几行，包含上下文）
3. 你的环境：Mac、`.venv`、Python 版本

可以直接这样发：

```text
环境：Mac，VS Code，Python 3.12，已激活 .venv，用 openai 库。

报错信息：
[paste 完整报错]

相关代码：
[paste 代码片段]

我已经确认：包已安装、Key 能读到、base_url 与平台文档一致。
请给出最可能的 3 个原因，按可能性排序，每个配一句修改方法。
```

最后一句是关键：**让它排优先级并给具体改法**，比笼统问"为什么报错"有用得多。

# 进阶篇：用 AI 高效画科研图

## 一、数据图（Matplotlib / Seaborn）

先装环境：

```bash
source .venv/bin/activate
pip install matplotlib seaborn pandas
```

三个库的分工：

- `matplotlib`：画图的底层库，折线、柱状、散点、箱线图都靠它。
- `seaborn`：基于 matplotlib 的统计图封装，热力图、回归拟合图更好看。
- `pandas`：读取 csv 表格数据。

## 二、逻辑图（示意图、框架图）

流程图和架构图用 **Mermaid + AI**：Mermaid 是文本描述图表的语法，AI 帮你写代码，VS Code 装 Mermaid 插件后可以实时预览，再导出 svg 矢量图。无版权问题，很适合申报书和论文。

```text
帮我写 Mermaid 代码，绘制多模态大模型 DermGPT 的架构流程图。
结构：输入（图像 + 文本）→ 编码器 → 融合模块 → 输出诊断文本。
要求：横向布局，简洁学术风，只输出 mermaid 代码，不要解释。
```

使用流程：VS Code 装 Mermaid 插件 → 粘贴代码预览 → 调整布局 → 导出 svg。

备选工具：

- **Draw.io**（<https://diagrams.net>）：免费，可 AI 辅助生成框图，导出 pdf / svg。
- **Figma + AI 插件**：适合美化框架图，用于 PPT 或申报手册封面。

## 三、美化、配色与规范检查

1. 配色：`给这张科研图提供适合期刊的配色方案，4 组区分色，要求色盲友好。`
2. 排版：`这张图的坐标轴、图例、标题有哪些不符合学术规范的地方？应该怎么调整？`
3. 格式：`把图注改成符合中文核心期刊规范的形式。`

科研图硬性规范：不用花哨渐变；少用亮红亮绿（对色盲不友好）；全文字体统一；图注独立于正文；线条清晰。

## 四、缓解 AI 生图幻觉的四个手段

### 1. 提示词：把约束写死

- **明确禁止项**：`禁止扭曲、禁止乱码文字、禁止增加额外组件、禁止改变物体数量、禁止融合不同物体`
- **指定参考标准**：`符合学术绘图规范，线条平直，正交箭头，框图对齐`
- **拆分描述**：先定风格，再定结构，再定约束，最后负面提示词——不要一句话堆完所有要求

科研图负面提示词（可直接复用）：

```text
幻觉，扭曲，畸形，错乱，多余肢体，重复部件，乱码文字，模糊，渐变，花哨配色，水印，噪点，拼接错误，物体融合，数量错误，歪斜线条，杂乱背景
```

### 2. 给参考图：图生图 / ControlNet（抑制结构幻觉最强）

科研绘图首选这条路径，尤其适合挑战杯、攀登计划这类需要精确示意图的场景。

1. 先用 PPT / Visio / Figma 手画草图或线稿，只画骨架：结构、模块位置、箭头方向全部定死。
2. 送入 ControlNet 约束生成：

| 模式 | 锁定什么 | 适用场景 |
| --- | --- | --- |
| Canny（线稿） | 轮廓、位置、布局 | 框图、示意图首选 |
| OpenPose | 人物姿态 | 有人物的配图 |
| Depth | 空间深度关系 | 立体结构图 |
| Layout | 框布局 | 多模块排版图 |

关键参数：**重绘幅度 `denoising strength` 建议 0.3–0.5**。数值越低越忠于原图、幻觉越少；超过 0.7 容易重新"脑补"，结构就跑飞了。

### 3. 选模型、调参数

- **模型**：通用创意模型（Midjourney、DALL·E）想象力强但幻觉高；结构化模型（SDXL + ControlNet、各类 Diagram / 图表生成模型）幻觉明显更低。科研示意图优先用 **Diagram 专用模型**，而不是通用文生图。
- **采样器**：不必追求极高步数，20–35 步足够；Euler a 这类随机性强的采样器幻觉更高，DPM++ 2M Karras 更稳定。
- **分辨率**：低分辨率会诱发"乱补细节"，直接按最终尺寸生成（如 1200×1600），不要后期放大。

### 4. 只生成布局，文字后加

让 AI 只画线条和示意图框架，**所有文字、图注导出后在 Figma / PPT / Illustrator 里手动添加**。这一步能从根上消除文字乱码，科研配图强烈推荐按这个流程走。
